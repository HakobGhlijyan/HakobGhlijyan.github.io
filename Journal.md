## 1. The Big Picture
Личный сайт-портфолио iOS-инженера (Акоб Клиджян), размещенный на GitHub Pages. Цель проекта — отразить 5+ лет коммерческого опыта в экосистеме Apple, показать зрелый инженерный подход, приверженность принципам Clean Code и высокую планку качества UI/UX.

В качестве фундамента выбран эталонный дизайн-шаблон **StackCraft** (`2162_stackcraft`) с глубокой темной палитрой, акцентным золотисто-бронзовым цветом (`#c9a96e`), аккуратной типографикой (`Cormorant Garamond` + `Outfit`) и микроанимациями.

---

## 2. Architecture Deep Dive
Архитектура фронтенда построена по принципу максимальной нативности, чистоты и модульности без избыточных фреймворков и лишних зависимостей:
- **Семантический HTML5**: логическая структура разбита по четким секциям (`#hero`, `#about`, `#skills`, `#projects`, `#experience`, `#contact`). Каждая секция снабжена подробными Apple-style маркерами (`<!-- MARK: - ... -->`).
- **Модульный CSS3**: переменные (`:root`), гибкие сетки Grid и Flexbox, плавные переходы (`var(--ease-smooth)`), эффекты стекла (`backdrop-filter`) и темная тема с высоким контрастом.
- **Чистый Vanilla JavaScript**: легковесный модуль (`IIFE`), управляющий эффектом блюра шапки при скролле, раскрытием мобильного меню, пересечением элементов во viewport (`reveal`) и интерактивной контактной формой.

## 4. Tech Stack & Why
- **Vanilla HTML5 & CSS3**: обеспечивает мгновенную загрузку (<100мс), нулевые накладные расходы на бандлеры и идеальную совместимость с GitHub Pages.
- **Swift / iOS Focus**: блок интерактивного кода в Hero-секции написан на Swift с использованием современных парадигм (`struct`, `async throws`, `await`), демонстрируя профильную экспертизу инженера.
- **Apple Design & Clean Code Standards**: документация в коде оформлена в стилистике Apple Documentation (`// MARK: -`, двуязычные описания).

## 5. The Journey & War Stories
### Переход на StackCraft
Старая версия сайта использовала стандартный шаблон Bootstrap Grayscale с разрозненными страницами (`projects.html`, `resume.html`, `contact.html`). Информация была фрагментирована, а визуальный стиль не соответствовал современным стандартам Apple-разработчика.

**Что сделано в рамках первой итерации:**
1. Очищена устаревшая кодовая база Bootstrap.
2. Интегрирован эталонный шаблон StackCraft в качестве единого SPA-лендинга.
3. Интегрированы реальные данные из резюме:
   - SDEK (СДЭК) — гибридная архитектура UIKit + SwiftUI, оптимизация скорости рендеринга на 25%, локальные push-уведомления.
   - FinKeeper — финансовое приложение, кастомные Swift Charts, StoreKit (+15% конверсии), Core Data и биометрия.
   - SmartHome Keys — разработка IoT-платформы с нуля на SwiftUI + Combine, библиотека переиспользуемых компонентов.
4. Добавлены реальные контакты: Email (`hakobghlijyan@gmail.com`), GitHub, LinkedIn, Telegram (`@hakobghlijyan`).
5. Настроен вывод вертикального фото пользователя в секции About с сохранением пропорций и аккуратной композиции.

### Итерация 10: Поддержка тем (Dark & Light Mode), живой переливающийся песок и Clearwave-футер
- **Двухрежимная дизайн-система (Dark/Light)**: Разработана гармоничная палитра светлой темы («Warm Ivory & Champagne Bronze»), сохраняющая премиальный полиграфический характер портфолио. Настроено мгновенное переключение через SVG-кнопки (Солнце/Луна) в шапке и подвале с кинематографичным crossfade-блюром и сохранением состояния в `localStorage`. Внедрена подсветка кода в окне Swift, повторяющая Xcode Light.
- **Интерактивная канва золотого песка (Hero Sand & Dunes)**: Главный экран получил легкую 60fps-анимацию на нативном HTML5 Canvas: мягко переливающиеся барханы и мерцающие песчинки золота/бронзы с физикой отклонения от курсора мыши и автоматической сменой палитры при переключении темы. Через `IntersectionObserver` рендер полностью засыпает при скролле вниз, исключая нагрузку на процессор и аккумулятор.
- **Архитектурный футер в стиле Clearwave**: Подвал сайта реорганизован по образцу `templatemo_622_clearwave`: брендинг с кратким био, кнопки социальных сетей перенесены из секции контактов в подвал, развернуты колонки навигации, каталога приложений и ключевой инженерной экспертизы, а также добавлена кнопка возврата наверх.

### Итерация 11: Оптимизация потокового воспроизведения MP4 (FastStart), исправление рендеринга WebKit без внешних масок, видеодемо в Overview и нативный логотип Apple
- **FastStart и перенос `moov` атома в начало видео (MP4 Streaming)**:
  - Проблема: видеофайлы, экспортированные из видеоредактора, имели метаданные (`moov` atom) в самом конце файла (`kMDItemStreamable = 0`). При просмотре через локальные статические серверы (без поддержки HTTP 206 Partial Content) WebKit/Safari не мог начать воспроизведение, оставляя видео черным или прозрачным.
  - Решение: все 4 видеофайла (`Screenshot-iPhone-16-Pro-0.mp4`, `17`, `18-Pro`, `SE`) перепакованы без перекодирования с флагом `ffmpeg -c copy -movflags +faststart`. Метаданные теперь находятся в байте 0, обеспечивая мгновенный старт потокового воспроизведения.
- **Отказ от CSS-масок в пользу нативного `border-radius: 40px`**:
  - В WebKit любая задержка или ошибка пути при загрузке внешнего PNG для `-webkit-mask-image` приводит к рендерингу всего контейнера с нулевой прозрачностью.
  - Контейнер экрана переведен на `border-radius: var(--vid-radius, 40px)` с `overflow: hidden`, поверх которого с `z-index: 2` накладывается аппаратная рамка с прозрачным экраном. Это гарантирует 100% стабильный рендеринг без зависимостей от масок.
- **Видеодемо в разделе Overview (Пошаговый гид)**:
  - В левый список карточек гида добавлена 5-я интерактивная карточка: `▶ VIDEO DEMO: iPhone 18 Pro Video Demo`.
  - Раздел Overview переведен с единого статичного кавера на интерактивный холст: клик по шагам 1–4 показывает снимки каждого этапа, а клик по карточке видео переключает холст на мокап iPhone 18 Pro с возможностью воспроизведения/паузы.
  - При переходе в раздел Overview в JavaScript автоматически активируется первый шаг.
- **Интеграция официального логотипа Apple и отмена скругления бейджа**:
  - В кнопках шапки CentSweep и Nightwell векторный SVG заменен на пользовательский ассет `apple.logo@1x.png`, идеально соответствующий фирменному стилю.

### Итерация 27: Коронация золотого эталона — FilterStudio, унификация бургер-меню и армия шаблонов

Есть такой момент в каждом проекте, когда ты вдруг понимаешь: *это* — правильно. Не «достаточно хорошо», не «нужно доработать», а именно — *так и должно быть*. В этой итерации таким моментом стало решение коронировать FilterStudio в роли **golden master** — абсолютного эталона для всей экосистемы.

#### Почему FilterStudio?

CentSweep был первым — он строился органично, итерация за итерацией. Nightwell копировал его, но привносил своё. FilterStudio же создавался с нуля в тот момент, когда вся архитектура уже кристаллизовалась: ночная navy-палитра, центрированная навигация, чистый холст при загрузке, 72px QR справа. Всё на своём месте. Так FilterStudio стал не просто третьим сайтом — он стал **образцом**, которому теперь следуют остальные.

#### Война бургеров

Если когда-нибудь понадобится объяснить, почему стандарты существуют — история бургер-меню подойдёт идеально.

До этой итерации у каждого сайта были свои id, своя JS-логика, своя CSS-анимация. CentSweep использовал одну схему `open/close`, Nightwell — немного другую, FilterStudio — третью. Всё работало, но синхронизировать их было как дирижировать тремя разными оркестрами без единой партитуры.

Решение — хирургически простое: один стандарт, один контракт:
- `id="navBurger"` / `id="navClose"` — одни и те же имена везде.
- `setMenu(open)` — единая функция, переключающая `body.menu-open`.
- `role="dialog"` / `aria-modal="true"` — accessibility из коробки.
- `Escape` закрывает меню — потому что так ожидает пользователь.

После этого поддержка превратилась из «нужно помнить три разные схемы» в «везде одно и то же».

#### QR-код: 72px с характером

Маленький QR-код — большая проблема. Слишком большой — ломает баннер. Слишком маленький — не сканируется. Раньше значение подбиралось на глаз для каждого сайта.

Теперь: **72px + `min-width: 72px`** — фиксированный стандарт. На мобильных устройствах (≤ 640px) QR уходит вниз в V-стек под текстом, выравнивается по левому краю. Убрали `margin-left: auto` в мобильном overrides — иначе QR «уплывал» в центр и выглядел потерянно.

Маленькая деталь, которая делала мобильный вид некорректным — устранена и зафиксирована в стандарте.

#### Nightwell: -1px, который имел значение

`font-size: 16px` → `15px`. Один пиксель. Но именно он создавал ощущение, что Nightwell «немного тяжелее» остальных сайтов. Мозг замечает такие вещи даже без осознания — чуть больший кегль, чуть тяжелее шрифт кнопок, чуть жирнее табы. После синхронизации весов (`font-weight: 400` на lang-btn и portfolio-back-link) Nightwell встал в один визуальный ряд с FilterStudio и CentSweep.

#### Project-Template: армия пустых витрин готова к бою

Project-Template — это «болванка», которую можно наполнить за один день вместо двух недель. Нейтральная серо-сланцевая палитра (`#94A3B8`, `#CBD5E1`) выбрана не случайно: она не конкурирует с будущим брендингом приложения, не тянет в сторону «зелёного» или «синего». Просто элегантная основа.

Три копии — Project-4, Project-5, Project-6 — готовы. Вместо битых ссылок на несуществующие скриншоты — `canvas-demo-rect`: простые CSS-прямоугольники, которые честно показывают: «здесь будет картинка». Никаких 404, никаких сломанных иконок.

**Урок итерации**: Стандарт — это не ограничение. Это то, что позволяет двигаться быстро, не ломая уже построенное. `setMenu()` написана один раз. QR = 72px написан один раз. Font-size = 15px прописан в design token один раз. Дальше — только наполнение, а не переизобретение.

## Session — November 12, 2026 · Full Portfolio Audit & Standardization

**The goal:** One sweeping audit to make every site speak the same language — structurally, stylistically, semantically.

### What we fixed
- **FilterStudio** hamburger unified to `setMenu()` standard (the golden master)
- **CentSweep** hamburger rebuilt from scratch to match
- **Nightwell** header normalized: `font-size: 15px`, font weights, hamburger parity
- **Nightwell CSS** had a silent bug for weeks: `--font-serif` pointed to `'Instrument Serif'` but Google Fonts loaded `'Playfair Display'`. Rendering "worked" only because the browser found the preloaded font anyway — but the variable system was semantic garbage. Fixed all 15+ hardcoded occurrences to use `var()`.
- **Project-Template / 4 / 5 / 6** — `setMenu()` was entirely missing. The burger opened via inline `onclick=` and closed via raw `classList.remove`. Added the full standard block: `body.menu-open`, `aria-expanded`, Escape key, resize guard.
- **og:description** across all 4 template files was copy-pasted FilterStudio text. Replaced with generic.

### The lesson
When you copy-paste a site to create a new one, the metadata travels with it. `og:description`, footer legal lines, font variable names — these are invisible until someone audits. Run grep periodically: `grep -r "Filter Studio" Project-*/` catches these instantly.

### What's intentional (not bugs)
- FilterStudio QR = 638-byte placeholder PNG. It's a 1-bit palette PNG — perfectly valid, just tiny. Will be replaced with a real App Store QR when the app ships.
- `Project-Template/` has no link from root `index.html`. It's an internal scaffold, not a portfolio entry.
- `og:image` in templates uses relative paths. Fine for now — no OG sharing needed until real projects fill the slots.
